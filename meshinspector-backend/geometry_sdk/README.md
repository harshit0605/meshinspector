# Geometry SDK

Parallel in-house geometry SDK for MeshInspector.

This package is intentionally developed beside the current production MeshLib,
trimesh, and scipy integrations. Production services should not be migrated to
this SDK until each operation has parity tests and an explicit rollout gate.

## Development Rule

Only `geometry_sdk/adapters/*` and `geometry_sdk/io/*_adapter.py` should import
third-party geometry engines. Algorithm modules should work on `MeshDocument`
and NumPy arrays so the in-house implementation remains replaceable and
testable.

Rust accelerators live under `geometry-rs/` and must be called through
`geometry_sdk.accelerators` or `GeometrySDK`; production services should not
import `_zennah_geometry_rs` directly. Once a module is Rust-owned, keep the
Python module as a binding/compatibility wrapper only.

To rebuild the packaged uploaded fragments from local `storage/uploads`
artifacts:

```bash
uv run --extra dev python -m geometry_sdk.testing.uploaded_fragments --repo-root ..
```
