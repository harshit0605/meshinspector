# Zennah Geometry Rust Workspace

Optional Rust accelerators for `geometry_sdk`.

The Python SDK remains the public product API. Rust crates must stay behind the
accelerator boundary and must not import MeshLib, trimesh, scipy, or Python in
the pure core crate.

Hot query kernels use Rayon for data-parallel workloads. The PyO3 binding crate
releases the Python GIL while those Rust kernels run, then converts the finished
Rust outputs back to NumPy arrays.

## Crates

- `zennah-geometry-core`: pure Rust geometry kernels.
- `zennah-geometry-py`: PyO3/maturin extension module named `_zennah_geometry_rs`.
- `zennah-geometry-bench`: benchmark harness for generated and real fixture corpora.

## Core Module Layout

`zennah-geometry-core/src/lib.rs` is intentionally kept as the public facade.
Implementation code is split by domain:

- `analysis`: scalar-field summaries and other non-topological analysis reductions.
- `types`: public result structs, options, operations, and errors.
- `math`: shared vector math helpers.
- `mesh`: validation, stats, boundary loops, health summaries, adjacency, components, normals, and topology-neutral mesh utilities.
- `jewelry`: product-specific ring measurement and sizing kernels.
- `manufacturability`: product report assembly, recommendations, health scoring, and export-readiness decisions.
- `materials`: jewelry material density lookup and deterministic volume/weight conversion helpers.
- `repair`: low-risk mesh healing passes: close-vertex merge, degenerate-face removal, unreferenced-vertex compaction, outward orientation, ordered boundary loops, planar hole filling, and repair reports.
- `grid`: SDF grid indexing and interpolation helpers.
- `sdf_grid`: public SDF grid helper kernels for cell averaging, occupancy, volume estimation, interpolation, and gradient sampling.
- `spatial`: facade for cached AABB query handles, flat-BVH, closest point, raycast, winding, self-intersection, ray-thickness kernels, and exact-intersection groundwork. Private submodules keep AABB query ownership, BVH construction/traversal, closest-point search, ray traversal, float triangle predicates, MeshLib-directed exact integer predicates, two-mesh exact intersection extraction, exact contour ordering, MeshLib-style topology rewrite application, and winding math separate.
- `voxel`: SDF boolean/offset/shell value transforms, occupied-cell surface extraction, raw marching tetrahedra, SDF projection, and voxel refinement.
- `voxel_mesh_ops`: product-facing mesh-in/mesh-out voxel offset, shell, boolean, service-parity global thickening, and SDF-rebuild orchestration built from resident Rust field sampling, value transforms, extraction, and refinement kernels.
- `hollow_service`: fixed-thickness service hollowing contract that mirrors the app's current MeshLib `offsetMesh` plus `boolean(DifferenceAB)` workflow through the Rust SDF shell path.
- `health_service`: service-shaped health payloads that mirror the current MeshLib `findSelfCollidingTrianglesBS` plus hole-count contract while reusing Rust topology and BVH predicates.
- `sdf_marching`: finalized SDF marching mesh extraction, including SDF-guided orientation and repair after raw triangulation.
- `deform`: Laplacian smoothing, falloff weights, local offsets, and brush composition.
- `deform_smooth`: service-parity global smoothing kernels, including Taubin-style alternating Laplacian passes.
- `deform_target`: service-parity target/deficit-driven deformation kernels.
- `resize`: axis-aware radial scaling and ring-size resize kernels with protected-vertex falloff.
- `topology`: face-orientation traversal.

`zennah-geometry-py/src/lib.rs` is also intentionally kept as a small facade.
The binding code is split into domain modules (`analysis`, `mesh`, `jewelry`,
`manufacturability`, `repair`, `spatial`, `aabb_tree`, `voxel`, `sdf_marching`, `deform`, `deform_smooth`, `deform_target`, `resize`, `boolean`, and `topology`) plus shared
NumPy conversion helpers.

## Local Commands

Install Rust and maturin first:

```bash
rustup toolchain install stable
uv tool install maturin
```

Then run:

```bash
cargo fmt --all --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo bench -p zennah-geometry-bench --bench mesh_stats
uv tool run maturin develop --manifest-path geometry-rs/crates/zennah-geometry-py/Cargo.toml
GEOMETRY_SDK_ACCELERATOR=rust uv run --extra dev pytest tests/test_geometry_sdk_accelerators.py -q
uv run --extra dev pytest tests/test_geometry_sdk_performance.py -q
```

The production app must not import `_zennah_geometry_rs` directly. Use
`geometry_sdk.accelerators` or `GeometrySDK`.
