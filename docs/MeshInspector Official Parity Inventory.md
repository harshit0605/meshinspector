# MeshInspector Official Parity Inventory

## Purpose

This inventory maps official MeshInspector and MeshLib product surfaces to the current Zennah MeshInspector workbench contract. It is the guardrail for parity work: a feature is only treated as available when the backend manifest names the official source, MeshLib reference source paths, Rust owner modules, exposed commands, and validation gates.

Official sources used for this inventory:

- MeshLib feature index: https://meshlib.io/features/
- MeshInspector product page: https://meshinspector.com/
- MeshLib plugin documentation: https://meshlib.io/documentation/HowtoAddPluginOverview.html
- MeshInspector knowledge base pages for mesh objects, selection, measurement, offsetting, mesh-to-voxels, and mesh cut/measure.

## Status Rules

- `implemented`: the exposed product command is backed by Rust-owned geometry kernels and has focused validation gates.
- `partial`: some official behavior is available, but either the official UI surface is broader, host workflows are still app-specific, or parity tests do not yet cover the whole MeshLib feature.
- `missing`: the official feature area is not exposed in the app yet.
- Rust owner modules are `geometry-rs/...` files only. Python `geometry_sdk/...`, API, and frontend files are bridge or host integration modules; they should not be treated as algorithm owners.

## Validation Gates

The backend manifest inventory is validated by:

```bash
cd meshinspector-backend
uv run --extra dev pytest tests/test_meshinspector_official_parity_inventory.py -q
```

Feature-specific rows list their own Rust, backend, and workbench gates in `api/routers/versions.py`. New official tools should not be enabled in the official MeshInspector UI host until the corresponding row moves from `missing` to `partial` or `implemented` and the command capability is Rust-backed or explicitly marked as a non-geometry host workflow.
